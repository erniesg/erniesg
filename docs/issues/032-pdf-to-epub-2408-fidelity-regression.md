# Close the 2408.10903v5 PDF-to-EPUB fidelity regression

depends-on: 023,024,025,026

## Provider

vm-codex

## Goal

Turn the failures observed on public paper `2408.10903v5` into a deterministic, privacy-safe upload-to-preview-to-EPUB regression gate: continuous prose must preserve source-backed word boundaries and inline structure, the paper title must not be duplicated or reinserted into body prose, figures/diagrams, tables, and equations must render through truthful source-backed representations, and the studio must let the reader inspect the generated Mobile, Paper Pro Move, and Paper Pro renditions before optionally downloading the corresponding checked EPUB.

## Acceptance tests

- Add repository-owned synthetic fixture reductions for each observed failure class: title/author/body region separation without a duplicated title, discretionary line-end dehyphenation without changing authored hyphens, no isolated one-character paragraph fragments, figure/caption materialization, semantic-table-or-bounded-image fallback, and source-backed display-equation fallback. The fixtures are generated by `tests/fixtures/pdf/generate-fixtures.mjs`, recorded in `tests/fixtures/pdf/manifest.json`, and contain no bytes or prose copied from the named paper.
- A deterministic reconstruction assertion proves each canonical body span appears exactly once and in source order; the normalized document title appears once as the canonical title node and may also exist as EPUB package metadata, but is never injected into the abstract, author block, body paragraphs, captions, or page-boundary joins.
- Line-boundary decisions account for every source line transition as space, no-space join, preserved lexical hyphen, removed discretionary hyphen, or explicit unresolved evidence. The regression fixture has zero `unresolvedCorruptingJoinCount`, no cross-column or cross-region join, no orphan punctuation or isolated alphabetic fragment, and repeated import produces byte-identical decision records.
- Supported italic, bold, bold-italic, superscript, subscript, safe-link, citation, and footnote-marker spans have 1.0 mapped coverage and semantic preview/EPUB parity. Footnote markers resolve to typed note bodies and backlinks; unresolved citation-versus-note evidence remains review-required. Relative title, section-heading, body, caption, affiliation, and note hierarchy preserves its semantic ordering without copying absolute PDF font sizes.
- Numbered and unnumbered sections, nested lists, references, and bibliography entries remain typed, ordered structures. Heading acceptance requires geometry plus syntax, list markers never become isolated prose nodes, and bibliography entries do not merge across columns or leak out of their section.
- Every source-backed figure or diagram expected by the synthetic fixture becomes a visible preview occurrence and a packaged EPUB asset with a stable source hash, source bounding box, caption relationship, non-empty dimensions, and no placeholder or full-page screenshot. Repeated use of one content-addressed asset remains repeated semantic occurrences.
- Diagram extraction records source object/region ids, bounded geometry, asset hash, caption provenance, and canonical placement. Each complete accepted caption remains anchored to its figure, table, or equation at a meaningful reading-order position; neither an orphan label nor a relocated caption satisfies the gate.
- A table is emitted as semantic HTML only when its row/column structure validates; otherwise the exact bounded table region is emitted as a sharp image fallback with its caption and provenance. A table may not disappear, become undifferentiated body prose, or be represented by an empty border.
- MathML is emitted only when recoverable from source semantics. Otherwise each display equation uses a bounded source-backed SVG or raster fallback, preserves its source order and visible label when present, and never invents LaTeX, MathML, variables, or an equation number.
- Reflowed Mobile and e-ink renditions consume canonical reading order, not the source PDF's column coordinates. Assertions reject alternating-column prose, column-shaped whitespace, source-line mimicry, and captions/floats placed according to raw page coordinates instead of semantic relationships.
- Uploading the synthetic fixture at `/research/studio` renders the actual generated EPUB rendition rather than a parallel paper-only approximation. A fresh upload invalidates every previous reconstruction, object URL, receipt, preview, and download even when filename metadata is reused. The user can switch among continuous Mobile, Paper Pro Move (`954 × 1696` device pixels), and Paper Pro (`1620 × 2160` device pixels) previews; each control exposes selected state and the exact profile id/version, derives scaled browser geometry from the target registry, and labels pagination/font/orientation behavior as authoritative, advisory, or reader-controlled.
- Each supported preview has a matching, structurally checked optional download action. Switching preview profiles does not trigger a download, and each downloaded artifact's profile id, artifact hash, canonical node sequence, figure/caption relationships, and packaged assets match the preview receipt.
- Browser coverage verifies the upload, processing state, preview switching, visual/table/equation presence, continuous prose DOM order, optional download controls, accessible selected states, and absence of clipping, overlap, horizontal overflow, missing canonical nodes, generic placeholders, duplicated titles, and premature `EPUB ready` copy.
- The public paper is an opt-in trusted-VM acceptance input, never a committed fixture. The accepted source is identified by public id `2408.10903v5`, size `8873089`, and SHA-256 `f5c8f963c4d17409b6ab163e0be914db139f9bc83cca0274a88863098e865a80`. A private runner reads its path only from `SRT_PRIVATE_PDF_2408_10903V5`, verifies the hash before parsing, and writes all unpacked EPUBs, screenshots, traces, and gold comparisons to an owner-only directory outside the repository.
- The trusted-VM paper run exports Mobile, Paper Pro Move, and Paper Pro artifacts twice. Same-profile artifact hashes and privacy-safe reconstruction receipts are byte-identical across repeats; the benchmark comparator reports no structural, coverage, reading-order, relationship, unresolved-object, or ready-to-review regression against the frozen accepted baseline.
- Private-paper evidence contains only the public id/basename, source SHA-256, aggregate counters, normalized candidate boxes, diagnostic codes, profile/toolchain/schema versions, artifact hashes, timings, and pass/fail results. It contains no source text, image bytes, font names containing paths, absolute local paths, PDF bytes, EPUB bytes, screenshots, or browser traces in Git, GitHub issues, PR comments, or committed `.agent/evidence`.

## Stop conditions

Stop before committing or uploading the named PDF, copying its prose or figures into fixtures or snapshots, recording an absolute source path, hard-coding the public paper id/title in parser behavior, inventing table cells or math semantics, hiding unresolved objects, weakening completeness/readiness gates, substituting a full-page screenshot for a bounded object, or claiming pixel parity with reader-controlled EPUB firmware.

## Human clarification protocol

If a source object or line join remains ambiguous, report only the public paper id, page number, normalized candidate boxes, stable region/object ids, diagnostic codes, aggregate impact, and the smallest bounded choice. Keep screenshots and source snippets in the owner-only external review directory and ask the human to accept one existing source-backed candidate or hold the issue; do not paste private evidence into GitHub.

## Recommended response

Treat this paper as an integrated acceptance case, not a parser special case: reduce every observed failure to redistributable synthetic evidence, make preview and EPUB consume the same canonical semantics, and preserve ambiguity as an explicit review state.

## Trade-offs

Reflowable EPUB cannot guarantee the exact pagination, fonts, or orientation of every e-ink firmware. Profile-specific preview and receipts can truthfully prove the publisher-controlled graph, CSS, assets, and intended viewport while clearly separating reader-controlled behavior. Requiring a hash-verified external paper run makes VM validation slower but prevents a synthetic-only fix from declaring success against the reported regression.
