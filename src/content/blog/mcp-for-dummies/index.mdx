# Model Context Protocol (MCP) for Dummies, or, Why Not Just APIs?

If like me, you've wondered: isn't MCP just like APIs? Inspired by Gang Rui's sharing at [Chop Chop Talk Shop (Chomp Edition): Model Context Protocol](https://lu.ma/osacsvb9) hosted by Lorong AI, hopefully this post will make it clear why MCP is useful if you are a lazy developer who wants to build as many AI applications as possible with minimal effort.

## The Problem: Combinatorial Explosion of Developmental Effort

Suppose we want to send emails from our AI application serving doctors for a hospital. Before MCP, you'd write the integration logic to call an email API, handle its response, and wire it to the model. Now imagine doing this for appointment reminders over patient phone-calls, and for other apps like e-commerce sale notifications — all using the same email API. Without MCP, you'd re-implement the same integration logic across multiple clients, use cases, and environments. Any breaking change in the email API? I hope you enjoy refactoring in n² places.

MCP solves this by letting developers implement the logic *once* in a standard format, and reuse it *everywhere*. It’s like what React components did for UI — modular, declarative, and composable.

## What is MCP?

Just as USB-C eliminated the need for multiple cables and ports, MCP provides a universal way for AI apps to talk to external tools and data sources. The [key components](https://modelcontextprotocol.io/docs/concepts/architecture) are:

- **MCP Hosts**: AI applications that initiate requests and handle user interaction — like [Claude Desktop](https://claude.ai/download). A host can connect to multiple MCP servers through clients.
- **MCP Clients**: Built into hosts, they take care of server interaction. Each client connects to a single MCP server.
- **MCP Servers**: Expose tools, prompts, or resources for the client to use.

Anyone can write their own host, client, or server — or simply plug into the 4200+ existing capabilities on [Smithery.ai](https://smithery.ai).

## How It Works

User starts your AI application → makes a request (e.g. “Remind so-and-so about their appointment”) → the MCP client checks if it has the right tool (like `send_email`) and enough context → it invokes the tool via an MCP server — a small process running locally (via `stdio`) or remotely (via [HTTP+SSE](https://modelcontextprotocol.io/docs/concepts/architecture#transport-layer)) → the server processes the request and returns the result → the AI includes it in its response → user sees the final reply.

## Why MCP?

MCP enforces **separation of concerns**, promotes **reusability**, and drastically simplifies **maintenance**. If your goal is to reimagine software for an AI-native world, MCP keeps you from repeating yourself to death. In an MCP world, you can reuse what is already available, write what you need, and let the AI decide *what*, *when* and *how* to use tools.

### The Magic: AI Healthcare App Example

In the real world, user needs grow fast — and so do the platforms we need to support.

Say you’re building an AI-powered healthcare app that sends appointment reminders via **email**, **SMS**, and **in-app portal messages**.

Here’s how you'd structure it with MCP:

- **1 host per platform** (e.g. web, mobile)
- **3 clients inside each host** - One for each channel: email, SMS, in-app
- **Each client connects 1:1 to an MCP server** that handles the actual logic

Want to support WhatsApp next? Just reuse something if it exists or write a new server and it is immediately available to all hosts.

This model gives developers plug-and-play extensibility, minimal coupling, and consistent behavior across devices — all without duplicating effort.

## Beyond APIs

APIs are great, but MCP is better. It standardizes how integrations work in an AI-native world, enabling developers to move faster, reuse more, and scale smarter.

1. **Composable by Design** - APIs require you to manually wire logic for each use case, tightly coupling integration and interface. MCP's' separation of tools from usage makes it easy to remix capabilities, swap parts, and extend features without touching the rest of the system.
2. **Universally Reusable** – APIs make functions reusable within one app. MCP tools are reusable across apps. Build once, use anywhere. Fix once, everywhere benefits.
3. **AI-Native Execution** – Rather than hardcoded triggers used by APIs, MCP allows your application to flexibly adapt to free-form interactions and context.

In short: APIs expose functions. MCP enables architecture — composable, scalable, and orchestrated by AI.

It’s the difference between calling a service and orchestrating intelligent, flexible workflows at scale. Just as web devs moved from static HTML to reusable components, MCP helps AI engineers move from integrations that are brittle and fixed to dynamic, context-aware agentic software that respond to user needs in real time.

## Beyond Anthropic

Introduced by Anthropic, MCP is growing rapidly with support from major LLM players and community contributions.

* **OpenAI** officially supports MCP in their [Agents SDK](https://openai.github.io/openai-agents-python/mcp/), with OpenAI API and ChatGPT desktop app [coming soon](https://x.com/OpenAIDevs/status/1904957755829481737)
* **Microsoft** developed the [official C# SDK](https://github.com/modelcontextprotocol/csharp-sdk) for MCP, integrating the protocol into Copilot Studio, VS Code's GitHub Copilot agent mode, and Semantic Kernel
* Major platforms like [GitHub](https://github.com/modelcontextprotocol/servers), [Slack](https://modelcontextprotocol.io/clients), and [Cloudflare](https://developers.cloudflare.com/agents/model-context-protocol/) added official MCP connections
* Many official language SDKs available: [Python](https://github.com/modelcontextprotocol/python-sdk) (Anthropic), [TypeScript](https://github.com/modelcontextprotocol/typescript-sdk) (Anthropic), [Java](https://github.com/modelcontextprotocol/java-sdk) (Spring AI), [C#](https://github.com/modelcontextprotocol/csharp-sdk) (Microsoft), [Kotlin](https://github.com/modelcontextprotocol/kotlin-sdk) (JetBrains), [Swift](https://github.com/modelcontextprotocol/swift-sdk) (Loopwork AI), and [Rust](https://github.com/modelcontextprotocol/rust-sdk) (Anthropic)

The ecosystem is in its early days, and the quickest way to test the waters is to connect a host to tools yourself.

## Getting Started

I've found it easiest to try MCP out as a user as follows:

1. **Get a Client**:
   - Download Claude Desktop: [claude.ai/download](https://claude.ai/download) or any [existing host](https://modelcontextprotocol.io/clients).

2. **Handle Dependencies:
   - Install [Node.js](https://nodejs.org/en/download) if you do not already have it.

3. **Find Tools**:
   - Browse [smithery.ai](https://smithery.ai) and use it to set up clients for you
