RAGgaeton パッケージは、人間とコンピューターの協働を試す実験として作った。人間の創造性と A.I.（人工知能）の強みを組み合わせて、オリジナルなコンテンツ制作をスケールさせるためのものだ。このブログでは、RAGgaeton の着想、主要機能と利点、実際のデモ、技術的な苦労と学び、そして A.I. で拡張されたコンテンツ制作の今後について書く。

## RAGgaeton が生まれたきっかけ

正直に言おう。A.I. の学習に使えるデータは、世界的に枯渇しつつある。そこで考えた。A.I. を、人間がオリジナルなコンテンツを生み出すための増幅器として使えないか。学習データがますます希少になる一方で、コンテンツは量の面でも質の面でもまだ足りない。ならばこの領域で A.I. が役に立てる余地は、かなりあるはずだ。

僕にとって、*オリジナルな*文章を書くときには、システム1的な思考とシステム2的な思考のあいだに、いつも大きな溝がある。頭の中には下書きのアウトラインがあるし、言いたい主張の輪郭もだいたい見えている。けれど、情報を集め、使える形に整え、腰を据えて文と段落にしていく作業はどうか。まったく進まない。手元にリサーチアシスタントの軍団でもいればいいのに……。

そこで登場するのが、**検索拡張生成**（RAG）で動く **大規模言語モデル**（LLM）だ。救援部隊である。

RAGgaeton は LLMs と RAG の力を使ってこの溝を埋める。自分たちが選んだ信頼できる情報源に足場を置きながら、オリジナルなコンテンツを大規模に作れるようにする。

## デモ: RAGgaeton を動かしてみる

RAGgaeton は、自分のデータから任意の種類のコンテンツを自動生成するために作ったパッケージだ。僕自身、そしてたぶん多くの人が文章を書くときに直面している、いくつかの問題を解くために設計している。

1\. LLM の文章はクリシェっぽすぎる

2\. さまざまな情報源から情報を集め、取り出す必要がある

3\. 一貫性と整合性を保つ必要がある

4\. 編集と反復ができる、スケール可能で再現性のある創造的アウトプットが欲しい

## RAGgaeton がやること

書く時間が足りない？問題なし。RAGgaeton はコンテンツ生成をエンドツーエンドで自動化できる。

1\. リサーチクエスチョンを考える（もちろん、最初のトピックは自分で入れる必要がある）

2\. リサーチする

3\. 見出しを生成する

4\. 記事全体を下書きする

5\. TextFX を適用する（頭韻で書き換える、アイデアを展開する、など）

RAGgaeton は、最初のアイデアを入れて、あとは動かし、生成された下書きを編集・修正する形で使える。今後のバージョンでは、編集しやすいインターフェイスを実装し、一度書けばどこにでも公開できるようにしたい。

## 主要機能と利点

さまざまなコンテンツ種別と処理のつなぎ方にスケールできるように作った。しかも最新鋭の ColBERT 検索モデルを活用している（研究者の言葉であって、僕の盛りではない）。これによって、生成に必要なもっとも関連性の高いチャンクを取り出せる。

### スケールできるコンテンツ生成

ユーザーは再利用可能なコンテンツブロックを一度定義し、それらを組み合わせて、必要な記事タイプを作れる。動き方を少し見せる。

1.  まず `content_blocks.json` で再利用可能なコンテンツブロックを定義する
    

```json
  "Setting the Scene": {
    "description": "Introduce the setting with vivid descriptions to immerse the reader.",
    "details": {
      "optional": [
        "Time of Day",
        "Weather Conditions"
      ],
      "required": [
        "Location Description",
        "Atmosphere"
      ]
    }
  }
```

2.  次に、これらのコンテンツブロックを `article_{article_type).yaml` 内の候補構造へ組み立てるプロンプトを、こんなふうにコピーして編集する
    

```yaml
generate_draft_travel:
  system_prompt: |
    You are an expert travel writer skilled in creating compelling and engaging content for online publications. Always respond with a structured, valid JSON, adhering strictly to the provided example format. Do not include any other text or explanations outside of the JSON structure.
  message_prompt: |
    Task: Given the following context, generate an updated structure for a Travel Article to be published.

    Context:
    - Headline: {headline}
    - Hook: {hook}
    - Thesis: {thesis}
    - Article Types: {article_type}
    - Topics: {topics}
    - Context: {context}
    - Data: {optional_params[data]}
    - Publication: {optional_params[publication]}
    - Country: {optional_params[country]}
    - Personas: {optional_params[personas]}
    - Desired Length: {optional_params[desired_length]} words
    - Scratchpad: {optional_params[scratchpad]}

    You may use the possible structures below as a starting point. Each structure is composed of content blocks. Rewrite, reorder, substitute, remove, add new or simply flesh out further details for the structure and content blocks so as to be coherent with your headline, hook and thesis.

    Please provide the response in the following structured JSON format:

    {{
      "draft_outlines": [
        {{
          "content_block": "Introduction",
          "details": "[Content Block Details]"
        }},
        {{
          "content_block": "Personal Circumstances",
          "details": "[Content Block Details]"
        }},
        {{
          "content_block": "Destination Overview",
```

3.  あとは関連パラメータと `article_type` の値を添えて `generate_draft` エンドポイントを呼べば、生成開始だ。
    

P.S. コンテンツブロックを構造へ並べる部分は、手で書く代わりにアルゴリズムで順列生成できる。今後の課題かもしれない。

### A.I. によるリサーチと検索

RAGgaeton は書くだけではない。リサーチもする。さまざまなプラットフォームで追加調査するためのキーワード群を生成し、検索を実行し、その情報をデータベースに保存する。文書単位の埋め込みではなく、トークン単位の late interaction（後段相互作用）を使うことで、RAGgaeton はコンテンツにもっとも関連する情報を探し出し、正確さと深みを確保できる。現状の実装は `you.com` と `Obsidian vaults` に対応しており、今後さらに情報源を増やす予定だ。

### TextFX による創造的な強化

TextFX で、普通の文章を読み手を引き込む文章に変える。頭韻を足す、複雑なアイデアを展開する、ある単語を似た響きのフレーズへ爆発させる、などなど。すべて簡単な `edit-content` コマンドでできる。

## 技術スタック

技術まわりが気になる人向けに書くと、RAGgaeton は次の構成でできている。

1.  自然言語生成には Claude 3.5 Sonnet と GPT-4o
    
2.  データベース管理には Supabase
    
3.  トレーシングとモニタリングには Langfuse
    
4.  効率的な情報検索には Llama Index（その先には、文書やデータを相手にしたステートフルなチャットも！）
    
5.  データ検証には Pydantic
    
6.  `generate-research-questions`、`do-research`、`generate-headlines`、`generate-draft`、`generate-topic-sentences`、`generate-full-content`、`edit-content` を公開する、単位ごとに分けた API エンドポイントには FastAPI
    

この組み合わせによって、RAGgaeton は一貫性と整合性を保ちながら、文脈に合った高品質なコンテンツを出せる。

### タスク

素の LLM クライアントには、このプロンプトをもとに、Fu Gai Mountain へのハイキングについての旅行記事を書かせた。

```text
write me a 600 word travel article about hiking to fu gai mountain in zhejiang
Scratchpad: I saw an ant try to move a flower on the hike, it was doing so with all its might. When not doing gradient descent, an A.I. engineer had lots of fun climbing a physical mountain. I took a challenging route and ended up climbing over rocks and caves.
```

上の下書きメモにアクセスできたのは RAGgaeton モデルだけだ。つまり以下の出力は、限られた文脈 vs. 豊かな文脈（書き手の下書きメモつき）、ゼロショットの LLM 生成 vs. 複数ステップの LLM 生成、という 2 つの軸のバリエーションになっている。

### 判定

文脈内学習で渡した TextFX を適用したのは Sonnet 3.5 だけだった。ただし、望む長さに合わせてさらに調整する必要はある。全体として、今回見たサンプルの中では、文章面でいちばん価値が高い出力だと感じた。

## 僕の設計思想

RAGgaeton を作るうえで、意識している原則は大きく 3 つある。

1\. **持ち運べるデータ**：あなたのコンテンツはあなたのものだ。複数のプラットフォームやツールをまたいで、アクセスでき、使えるべきである。

2\. **自分固有のニーズに合わせて調整できること**：モデルの挙動、出力の編集、ワークフローの運用化、根拠づけなどについて、ユーザーが細かく制御できるべきだ。

3\. **アジア言語を第一級で支えること**：これは僕にとって個人的に思い入れのある領域だ。ウェブ上では、中国語のような言語がいまも過小代表されている。

## 学びと課題

RAGgaeton を作る過程は、発見と課題だらけだった。主な学びをいくつか挙げる。

### 抽象化 vs 具体性

このトレードオフのバランスを取るのは、常に難しい。いつまでに何を達成したいのかから逆算し、最終目標を個別の要素に分解し、どの部分をより再利用可能にすべきかを見るやり方が役に立った。

その結果、`llm_handler.py`、`llm_processing.py`、`prompts.py` を切り出した。`llm_handler.py` は `prompts.py` で整形されたプロンプトを使って呼び出し、`llm_processing.py` はレスポンスを解析して、こちらのエンドポイントときちんと噛み合うようにする。こうして各操作を小さな単位に分ければ、どうつなげるかを自由に決められる。

### 確率的モデルを、決定的に振る舞うよう縛る

苦労したことのひとつは、言語モデルから予測可能な挙動を引き出すことだった。対策として、Pydantic でリクエストとモデル出力に厳密なスキーマを定義した。こうした制約がないと何が起きるか、例を見せる。

![](./Screenshot-2024-06-20-at-6.13.05-PM-21719064449341.png)

片方では `attraction` と `description` が `details` キーの内側に入れ子になっていて、もう片方では代わりに `attraction_#` があり、その中にさらに `name` と `description` が入れ子になっていることに注目してほしい。これらのモデルは本当に「創造的」なので、従来のプログラミングパラダイムに対して予測可能で後方互換になるよう、きちんと手を入れる必要がある。

### RAG の未来

プロンプトエンジニアリング、RAG、ファインチューニングは、A.I. エンジニアの道具箱に入っている別々の道具だと思っている。コンテキストウィンドウやその他の条件がどう変わっても、RAG は残る。直感的にも、文脈に含まれるノイズとシグナルの比率が性能に効くのは自然だ。モデルはまだ、世界トップクラスの人間の専門家のように不要な情報を切り捨て、目の前のタスクに照準を合わせられる段階には来ていない。

## RAGgaeton の次にやること

RAGgaeton は継続的に改善している。次に取り組むのを楽しみにしていることをいくつか挙げる。

1\. **評価と出典**：失敗したときだけ通知してくれる自動評価と、どのコンテンツ断片がやや足元の怪しい根拠に乗っているかを示す出典管理の仕組みを実装したい。

2\. **リファクタリングと組み合わせやすさ**：Pydantic のスキーマはまだ少し散らかっているので、整理して重複を避けたい。

3\. **中国語の生成**：これは特に楽しみにしている拡張だ。A.I. がもっとこういう言葉を書けたら、よくないですか。

## 生成 A.I. で未来を一緒に書き直す

RAGgaeton を作ったのは、人間と A.I. の協働には、コンテンツの量と質の両方をスケールさせる力があると信じているからだ。言語や情報格差のような知識への障壁を壊せば壊すほど、より多くの人が恩恵を受けられる。

中国語話者は世界人口の 17% を占めるのに、ウェブ上の中国語コンテンツはわずか 1.3% しかない。RAGgaeton のようなツールで取り組みたいのは、まさにこういう不均衡だ。世界の知識に手元からアクセスするうえで、言語が障壁であってはならない。

書き手、コンテンツ制作者、あるいは A.I. とコンテンツ制作の交差点に関心のある人なら、RAGgaeton の開発を形にしていくうえでぜひ一緒にやりたい。

この取り組みに関わってみたい人は連絡してほしい。一緒に、コンテンツ制作のあり方を変えられる。もっと効率的に、もっとスケールしやすく、誰でも使いやすいものに。

未来を一緒に書こう。
