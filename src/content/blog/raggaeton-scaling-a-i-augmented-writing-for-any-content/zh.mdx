RAGgaeton是一个人机协作的实验，旨在利用人类创造力和人工智能（A.I.）的优势来扩大原创内容的创作。在这篇博文中，我将回顾RAGgaeton背后的灵感，解释其主要功能和优点，展示演示，讨论技术挑战和学习，并探索人工智能增强内容创作的未来可能性。

## RAGgaeton背后的灵感

事实是世界正在耗尽训练人工智能的数据。于是我有了一个想法——何不使用人工智能来增强人类原创内容的生成呢？训练数据变得越来越少的同时，原创内容的数量和质量一直都欠缺，想当然尔人工智能在这个领域还有很大的发挥空间。

对我来说，进行*原创*写作时，系统1和系统2思维之间总是存在着巨大的鸿沟。我脑海中一般会有一些草图，对我想要提出的论点有一个粗略的大纲。但是收集和整理信息，坐下来把它们打造成完整的句子和段落的任务呢？它们永远不会被完成。要是我们有一大批研究助理任我们支配就好了……

由检索增强生成（RAG）支撑的大型语言模型（LLM）可以让我们获救！

RAGgaeton利用LLM和RAG的力量来弥合这一差距，使我们能够大规模生产原创内容的同时把基础立于我们选择的真相来源。

## RAGgaeton 可以做什么

不够时间写作？没问题！RAGgaeton可以从头到尾自动化内容生成。

1\. 为你提炼关键词搜索哦（当然，你仍然需要提供主题）

2\. 进行搜索研究

3\. 生成标题

4\. 起草全文

5\. 应用TextFX（用头韵润色、扩展等）

你可以使用RAGgaeton来播种一个最初的想法，让它自己完成工作，然后编辑和修改生成的草稿。在未来的迭代中，我计划实现一个编辑友好的界面，这样你就可以一次编写并到处发布。

## 主要特性和优点

我将它构建为可扩展的，适用于不同的内容类型和链接内容上不同操作的方式，同时利用最先进的ColBERT检索模型（研究人员的话，不是我的）。这确保你为生成获取最相关的分块。

### 可扩展的内容生成

用户只需要定义一次可重用的内容块，然后混合和匹配以创建任何想要的文章类型。下面是它的工作原理。

1.  首先在`content_blocks.json` 中定义一个可重用的内容块
    

```json
  "Setting the Scene": {
    "description": "Introduce the setting with vivid descriptions to immerse the reader.",
    "details": {
      "optional": [
        "Time of Day",
        "Weather Conditions"
      ],
      "required": [
        "Location Description",
        "Atmosphere"
      ]
    }
  }
```

2.  接下来，复制并编辑一个提示符，以便将这些内容块组合成`article_{article_type).yaml` 中的可能结构
    

```yaml
generate_draft_travel:
  system_prompt: |
    You are an expert travel writer skilled in creating compelling and engaging content for online publications. Always respond with a structured, valid JSON, adhering strictly to the provided example format. Do not include any other text or explanations outside of the JSON structure.
  message_prompt: |
    Task: Given the following context, generate an updated structure for a Travel Article to be published.

    Context:
    - Headline: {headline}
    - Hook: {hook}
    - Thesis: {thesis}
    - Article Types: {article_type}
    - Topics: {topics}
    - Context: {context}
    - Data: {optional_params[data]}
    - Publication: {optional_params[publication]}
    - Country: {optional_params[country]}
    - Personas: {optional_params[personas]}
    - Desired Length: {optional_params[desired_length]} words
    - Scratchpad: {optional_params[scratchpad]}

    You may use the possible structures below as a starting point. Each structure is composed of content blocks. Rewrite, reorder, substitute, remove, add new or simply flesh out further details for the structure and content blocks so as to be coherent with your headline, hook and thesis.

    Please provide the response in the following structured JSON format:

    {{
      "draft_outlines": [
        {{
          "content_block": "Introduction",
          "details": "[Content Block Details]"
        }},
        {{
          "content_block": "Personal Circumstances",
          "details": "[Content Block Details]"
        }},
        {{
          "content_block": "Destination Overview",
```

3.  只需调用带有相关参数和`article_type`值的`generate_draft`端点，并开始生成！
    

附注：我们可以通过算法将内容块排列成结构，而不是将它们写出来，这可能是未来可以进行的工作。

### 人工智能研究与检索

RAGgaeton不只是进行写作；它还可以做研究。它会生成一系列关键词，以便在不同的平台上进行进一步的研究，执行搜索，然后将信息储存到数据库中。通过利用基于令牌的后期交互机制，而不是文档级嵌入，RAGgaeton可以为你的内容找到最相关的信息，确保准确性和深度。目前的实现支持`you.com` 和`Obsidian vaults` ，未来会持续加入更多信息源。

### TextFX的创意增强

用TextFX将普通的文章变成引人入胜的内容。添加头韵、展开复杂的思想、将一个单词分解成发音相似的短语等等——所有这些都只需要一个简单的`edit-content` 命令。

## 技术栈

如果你对科技感到好奇，RAGgaeton是由以下的组件所组成的:

1.  Claude 3.5 Sonnet和GPT - 4o自然语言生成
    
2.  Supabase用于数据库管理
    
3.  Langfuse用于跟踪和监控
    
4.  Llama Index用于高效的信息检索（以及随后与文档和数据进行有状态聊天！）
    
5.  Pydantic用于数据验证
    
6.  FastAPI用于开发利于原子操作的API端点，如`generate-research-questions`, `do-research`, `generate-headlines`, `generate-draft`, `generate-topic-sentences`, `generate-full-content`, and `edit-content`
    

这种结合使RAGgaeton能够在保持一致性和连贯性的同时提供高质量的、与上下文相关的内容。

## 我的设计理念

在创造RAGgaeton的过程中，我试图参考的三个关键原则如下：

1\. \*\***可移植数据**\*\*：你的数据应该是你的，可以在不同的平台和工具上访问和使用。

2\. \***可根据你的独特需求进行调整**\*\*：用户应该能够对模型行为进行粒度控制，编辑输出，调整操作工作流，着地感等。

3\. \*\***对亚洲语言的一流支持**\*\*：这是我个人的兴趣所在，因为目前像中文这样的语言在网络上的代表性不足。

## 学习和挑战

建设RAGgaeton是一段充满洞察力和挑战的旅程。以下是一些重要的经验教训：

### 抽象vs特异性

平衡这种取舍是一个持续的挑战。我觉得有效的是从我想何时实现什么功能为出发点，然后将最终目标分解为单个元素，看看是否其中任何部分是否应该更易于重用。

这导致我分离了`llm_handler.py`、`llm_processing.py`和`prompts.py`。 `llm_handler.py`使用由`prompts.py`格式化的提示符进行调用，`llm_processing.py`解析响应以确保它与我们的端点兼容。这样子的原子操作方便用户自由决定如何链接它们。

### 约束概率性模型进行确定性的行为

我面临的一个挑战是从语言模型中获得可预测的行为。为了解决这个问题，我使用Pydantic为请求和模型输出定义严格的数据模式。下面是一个没有这些限制的例子:

![](./Screenshot-2024-06-20-at-6.13.05-PM-21719064449341.png)

没有相关约束的话，LLM的输出有一回把`attraction` 和 `description` 嵌套于`details` 键值。另一回又在`attraction_#` 里面嵌套了`name` 和`description`。这些模型具有“创造性”，因此需要投入工作使它们具有可预测性并与传统编程模式向后兼容。

### RAG的未来

我认为提示工程、RAG和微调是人工智能工程师工具箱中的不同工具。无论上下文窗口或其他因素如何变化，RAG都将继续存在。直观地说，上下文中的噪声-信号比对性能很重要。我们还没有达到模型可以像世界级的人类专家那样专注于手头的任务且忽略不必要的信息。

## RAGgaeton的下一步是什么?

我一直在努力改进RAGgaeton。下面是一些让我感到兴奋的后续步骤:

1\. \*\***评估和引用**\*\*：我想实现自动评估，只有当它们失败时才提醒我，以及一个可以突出显示哪些内容块支撑不足的引用系统。

2\. \*\***重构和可组合性**\*\*：Pydantic模式仍然有点混乱，所以我希望清理它们并避免重复。

3\. \*\***中文生成**\*\*：这是一个让我特别兴奋的提升。如果人工智能能写出更多这样的文字，那不是很好的吗？

## 让我们（重新）用生成式人工智能书写未来

我建造RAGgaeton是因为我相信人类和人工智能协作以扩展内容的数量和质量的力量。我们越能消除语言和信息不对称等知识障碍，受益的人就越多。
