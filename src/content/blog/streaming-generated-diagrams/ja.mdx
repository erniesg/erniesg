# 作ってみた: Cloudflare Workers x Vercel AI SDK で、システム構成図を生成しながらリアルタイム配信する

*AI モデルが生成するそばから、複雑な構造化データをノード単位、エッジ単位でストリーミングする、リアルタイムのアーキテクチャ図生成器を作った。*

## 問題: テキストのストリーミングだけでは足りない

AI のストリーミング実装の多くはテキスト生成に寄っている。ChatGPT のタイプライター表示を思い浮かべればいい。でも、複雑な構造化データをリアルタイムに送りたい場合はどうするのか。AI モデルがネットワーク図を生成していく過程を、ノードごと、エッジごとに可視化したい場合は？

**vibetoprod** を作っているとき、まさにそこに取り組んだ。vibetoprod は、インタラクティブなクラウドアーキテクチャ比較を生成するツールだ。完全なレスポンスを 10 秒以上待つのではなく、AI が考えているそばから図がリアルタイムに立ち上がってくる体験にしたかった。

## 使ったスタック: エッジ前提のストリーミング

今回の、エッジ向けに組んだモダンなスタックはこうだ。

**バックエンド:**
- **Cloudflare Workers** - グローバルに低レイテンシを出すためのエッジコンピュート
- **Hono** - 軽量な Web フレームワーク（Workers 向けの Express みたいなもの）
- **Vercel AI SDK** - 構造化ストリーミングの秘伝のタレ
- **OpenAI GPT-4** - 構成を考える頭脳役
- **Zod** - 実行時のスキーマ検証

**フロントエンド:**
- **React + TypeScript** - 型安全な UI コンポーネント
- **React Flow** - インタラクティブな図の可視化
- **Server-Sent Events** - ブラウザへリアルタイムに流すための仕組み

## 肝: `partialObjectStream`

突破口になったのは、Vercel AI SDK の `partialObjectStream` だった。`streamText()` は多くの開発者が知っているけれど、`streamObject()` を知っている人は少ない。まして、その部分的なストリーミング機能となるとさらに少ない。

動き方はこうだ。

### 2. バックエンド: 部分オブジェクトをストリーミングする

```typescript
// functions/services/modernOpenAIService.ts
import { streamObject } from 'ai';
import { createOpenAI } from '@ai-sdk/openai';

export class ModernOpenAIService {
  private model: any;

  constructor(private apiKey: string) {
    const openai = createOpenAI({
      apiKey: this.apiKey
    });
    this.model = openai('gpt-4o-2024-08-06');
  }

  async streamArchitecture(input: UserInput) {
    const prompt = this.buildPrompt(input);

    return await streamObject({
      model: this.model,
      schema: architectureResponseSchema,
      prompt,
      mode: 'json'
    });
  }
}
```

### 3. Cloudflare Workers: Server-Sent Events

```typescript
// functions/[[route]].ts
app.post('/api/generate-architecture-v2', async (c) => {
  const userInput = await c.req.json();
  const modernOpenAI = new ModernOpenAIService(c.env.OPENAI_API_KEY);
  const result = await modernOpenAI.streamArchitecture(userInput);

  // Stream partial objects as Server-Sent Events
  const stream = new ReadableStream({
    async start(controller) {
      const encoder = new TextEncoder();

      // This is where the magic happens
      for await (const partialObject of result.partialObjectStream) {
        const chunk = `data: ${JSON.stringify(partialObject)}\n\n`;
        controller.enqueue(encoder.encode(chunk));
      }

      controller.enqueue(encoder.encode(`data: [DONE]\n\n`));
      controller.close();
    }
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
      'Access-Control-Allow-Origin': '*',
    },
  });
});
```

### 4. 自動レイアウト: Dagre でリアルタイムに配置する

大事な発見がひとつある。**レイアウトを AI に任せてはいけない**。LLM は空間的な配置が苦手だが、論理的な関係を生成するのは得意だ。なので、こうした。

1. `position: { x: 0, y: 0 }` 付きでノードを生成する（ただし無視する）
2. ストリーミング更新のたびに Dagre レイアウトを再実行する
3. 図が広がるたびにビューポートを自動でフィットさせる

```typescript
// src/utils/autoLayout.ts
import dagre from '@dagrejs/dagre';
import type { Node, Edge } from '@xyflow/react';

const nodeWidth = 172;
const nodeHeight = 50;

export const getLayoutedElements = (nodes: Node[], edges: Edge[], direction = 'LR') => {
  if (nodes.length === 0) return { nodes: [], edges };

  // Create fresh graph for each layout (no shared state)
  const dagreGraph = new dagre.graphlib.Graph();
  dagreGraph.setDefaultEdgeLabel(() => ({}));
  dagreGraph.setGraph({
    rankdir: direction,
    nodesep: 150,  // Space between nodes on same rank
    ranksep: 200,  // Space between ranks (layers)
    marginx: 80,   // Graph margin
    marginy: 80
  });

  nodes.forEach((node) => {
    dagreGraph.setNode(node.id, { width: nodeWidth, height: nodeHeight });
  });

  edges.forEach((edge) => {
    dagreGraph.setEdge(edge.source, edge.target);
  });

  dagre.layout(dagreGraph);

  const newNodes = nodes.map((node) => {
    const nodeWithPosition = dagreGraph.node(node.id);
    return {
      ...node,
      position: {
        x: nodeWithPosition.x - nodeWidth / 2,
        y: nodeWithPosition.y - nodeHeight / 2,
      },
    };
  });

  return { nodes: newNodes, edges };
};
```

面白いところはストリーミング用コンポーネントの中にある。**ノードがひとつ追加されるたびに**レイアウトを計算し直す。

```typescript
// src/components/streaming/StreamingReactFlow.tsx
useEffect(() => {
  if (reactFlowNodes.length > 0) {
    // Re-layout on every streaming update
    const { nodes: layoutedNodesResult, edges: layoutedEdgesResult } = getLayoutedElements(
      reactFlowNodes,
      reactFlowEdges,
      'LR'  // Left-to-right layout
    );

    setLayoutedNodes(layoutedNodesResult);
    setLayoutedEdges(layoutedEdgesResult);

    // Auto-fit viewport to new layout
    setTimeout(() => {
      if (reactFlowInstanceRef.current) {
        reactFlowInstanceRef.current.fitView({ padding: 0.2 });
      }
    }, 50);
  }
}, [reactFlowNodes.length, reactFlowEdges.length]); // Re-run on every count change
```

このやり方なら、**反応のよいリアルタイムレイアウト**になる。ノードがひとつ流れ込むたびに Dagre が全体の配置を再計算し、ビューポートもなめらかに追従する。**AI は論理的なアーキテクチャを生成し、見た目の整い方は Dagre に任せる**。

### 5. フロントエンド: 部分オブジェクトを破綻なく扱う

```typescript
// src/hooks/useStreamingArchitectureV2.ts
export function useStreamingArchitectureV2() {
  const [object, setObject] = useState<Partial<ArchitectureResponse> | null>(null);

  // Filter out incomplete objects before rendering
  const allCloudflareNodes = object?.cloudflare?.nodes || [];
  const cloudflareNodes = allCloudflareNodes.filter(node => {
    const isComplete = node &&
      typeof node === 'object' &&
      node.id &&
      node.type &&
      node.name &&
      node.position &&
      typeof node.position === 'object' &&
      typeof node.position.x === 'number' &&
      typeof node.position.y === 'number';

    if (!isComplete && node?.id) {
      console.log(`⏳ Incomplete node ${node.id}:`, node);
    }

    return isComplete;
  });

  // Stream processing
  const generateArchitecture = useCallback(async (userInput: UserInput) => {
    const response = await fetch('/api/generate-architecture-v2', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ input: userInput }),
    });

    const reader = response.body?.getReader();
    const decoder = new TextDecoder();
    let buffer = '';

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      buffer += decoder.decode(value, { stream: true });
      const lines = buffer.split('\n');
      buffer = lines.pop() || '';

      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const dataStr = line.slice(6);
          if (dataStr === '[DONE]') break;

          try {
            const partialObject = JSON.parse(dataStr);
            setObject(partialObject); // React re-renders with new data
          } catch (parseError) {
            console.warn('Failed to parse chunk:', dataStr);
          }
        }
      }
    }
  }, []);

  return {
    cloudflareNodes, // Only complete nodes
    // ... other filtered data
    generateArchitecture,
  };
}
```

## 学んだこと: 実際に分かったこと

### 1. **部分オブジェクトは少しずつ届く**
AI モデルは、ひとつのノードを完成させてから次に進むわけではない。Node A は ID だけ、次に Node B は途中まで、さらにその後で Node A が完成、という順番もあり得る。フロントエンドはこの未完成さを前提に処理しないといけない。

### 2. **検証はかなり重要**
描画する前に、部分オブジェクトは必ず検証する。必須フィールドが欠けていると React Flow は落ちる。UI ごと落とすくらいなら、未完成のオブジェクトは飛ばした方がいい。

### 3. **AI のロジックと見た目のレイアウトを分ける**
LLM に位置計算をさせてはいけない。空間推論が弱いからだ。AI には論理的なアーキテクチャを生成させ、レイアウトの自動配置は Dagre.js に任せる。そうすると、余白のきれいな見やすい図になる。

### 4. **Server-Sent Events > WebSockets**
一方向のストリーミングなら、SSE は WebSockets より単純だ。接続管理はいらないし、自動再接続もあるし、ブラウザ対応もよい。

### 5. **Cloudflare Workers はストリーミングと相性がいい**
Workers はストリーミングを意外なほどちゃんと扱える。`ReadableStream` API は Vercel AI SDK の `partialObjectStream` ときれいに噛み合う。

### 6. **段階的な描画は UX をよくする**
図がリアルタイムに組み上がっていくのを、ユーザーはかなり気に入る。合計時間が同じでも、ローディングスピナーよりずっと対話的に感じられる。

## 結果: アーキテクチャをリアルタイムに可視化する

作ったのは、こういうシステムだ。
- 複雑な構造化データをリアルタイムにストリーミングする
- 部分オブジェクトを破綻なく扱う
- 即座に視覚的なフィードバックを返す
- Cloudflare のエッジネットワークでグローバルにスケールする
- パイプライン全体で型安全性を保つ

ユーザーが「アーキテクチャを生成」をクリックすると、AI が考えているそばからノードと接続がすぐに現れる。建築家がリアルタイムに設計図を描いているのを横から見ている感じだ。

## 自分で試す

核になるパターンは単純だ。
1. Vercel AI SDK の `streamObject()` を `partialObjectStream` と一緒に使う
2. Server-Sent Events 経由でストリーミングする
3. フロントエンドで未完成のオブジェクトを除外する
4. オブジェクトが完成したものから段階的に描画する

このやり方は、データベーススキーマ、API レスポンス、設定ファイル、複雑な可視化など、どんな構造化データにも使える。

## エッジ上のハイパーパーソナライズ UI にとって、これが何を意味するか

このストリーミングアーキテクチャのパターンが開くのは、もっと大きな可能性だ。**リアルタイムに適応する、極度にパーソナライズされたインターフェース**である。

ただ速く読み込まれるだけではない。読み込まれながら、ユーザーごとの文脈に合わせて *変化していく* インターフェースを想像してほしい。

- **ダッシュボードウィジェット** が、いまのプロジェクト状態に応じて現れる
- **ナビゲーションメニュー** が、利用パターンに応じて並び替わる
- **フォーム項目** が、過去の入力に応じて姿を現す
- **商品レコメンド** が、閲覧しながら更新される
- **コード補完** が、入力に合わせて候補をストリーミングする

Cloudflare Workers のエッジコンピュートと Vercel AI SDK の構造化ストリーミングを組み合わせると、新しいパラダイムが見えてくる。**文脈に応じて自分で組み上がるインターフェース**だ。

全員に同じ UI を送り、クライアント側の JavaScript で個別化する代わりに、こうできる。
1. **ユーザーの文脈を分析する**。場所、デバイス、行動をエッジで見る
2. **AI モデルでパーソナライズされた UI 構造を生成する**
3. **生成されたそばからインターフェースコンポーネントをストリーミングする**
4. **段階的に描画する**ことで、すぐに速く感じられるようにする

これは特に、次のようなものに効く。
- **SaaS ダッシュボード** が、ユーザーの役割に合わせて自動構成される
- **EC インターフェース** が、購入行動に合わせて適応する
- **開発者ツール** が、文脈に応じて関連機能を前に出す
- **コンテンツプラットフォーム** が、エンゲージメントのパターンに応じて構造を組み替える

速さはエッジが担う。賢さは AI が担う。なめらかさはストリーミングが担う。

私たちが作っているのは、単に速い Web サイトではない。考え、適応し、ユーザーごとにリアルタイムで形を取るインターフェースだ。しかも、思考の速度で。

Web 開発の未来は、コードをより速く出荷することだけではない。ユーザーごとに *違うコード* を出荷することだ。エッジで生成され、ストリーミングされ、本当に個別化された体験を作る。ちょっと魔法っぽく感じるやつを。
