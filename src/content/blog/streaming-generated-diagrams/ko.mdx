# 만드는 법: Cloudflare Workers x Vercel AI SDK로 생성되는 시스템 아키텍처를 실시간 스트리밍하기

*AI 모델이 노드와 엣지를 하나씩 생성해 가는 동안, 복잡한 구조화 데이터를 실시간으로 스트리밍하는 아키텍처 다이어그램 생성기를 만든 이야기.*

## 문제: 텍스트 스트리밍을 넘어서

대부분의 AI 스트리밍 구현은 텍스트 생성에 맞춰져 있다. ChatGPT의 타자기 효과를 떠올리면 된다. 그런데 복잡한 구조화 데이터를 실시간으로 보내야 한다면? AI 모델이 네트워크 다이어그램을 노드 하나, 엣지 하나씩 만들어 가는 모습을 바로 시각화하고 싶다면?

**vibetoprod**를 만들면서 우리가 붙잡고 씨름한 문제가 정확히 그거였다. vibetoprod는 인터랙티브한 클라우드 아키텍처 비교 다이어그램을 생성하는 도구다. 완성된 응답을 받으려고 10초 넘게 기다리게 하는 대신, AI가 생각하는 동안 다이어그램이 실시간으로 형태를 갖춰 가는 모습을 사용자에게 보여 주고 싶었다.

## 우리의 스택: 엣지 우선 스트리밍

우리가 쓴 현대적이고 엣지에 최적화된 스택은 이렇다.

**백엔드:**
- **Cloudflare Workers** - 전 세계에서 낮은 지연 시간을 내기 위한 엣지 컴퓨팅
- **Hono** - 가벼운 웹 프레임워크(Workers를 위한 Express 같은 것)
- **Vercel AI SDK** - 구조화 스트리밍을 가능하게 해 준 핵심 도구
- **OpenAI GPT-4** - 아키텍처를 구상하는 엔진
- **Zod** - 런타임 스키마 검증

**프런트엔드:**
- **React + TypeScript** - 타입 안전한 UI 컴포넌트
- **React Flow** - 인터랙티브 다이어그램 시각화
- **Server-Sent Events** - 브라우저로 보내는 실시간 스트리밍

## 마법: `partialObjectStream`

돌파구는 Vercel AI SDK의 `partialObjectStream`에서 나왔다. 대부분의 개발자는 `streamText()`를 알고 있지만, `streamObject()`를 아는 사람은 더 적고, 그 안의 부분 스트리밍 기능까지 아는 사람은 더더욱 적다.

동작 방식은 이렇다.

### 2. 백엔드: 부분 객체 스트리밍하기

```typescript
// functions/services/modernOpenAIService.ts
import { streamObject } from 'ai';
import { createOpenAI } from '@ai-sdk/openai';

export class ModernOpenAIService {
  private model: any;

  constructor(private apiKey: string) {
    const openai = createOpenAI({
      apiKey: this.apiKey
    });
    this.model = openai('gpt-4o-2024-08-06');
  }

  async streamArchitecture(input: UserInput) {
    const prompt = this.buildPrompt(input);

    return await streamObject({
      model: this.model,
      schema: architectureResponseSchema,
      prompt,
      mode: 'json'
    });
  }
}
```

### 3. Cloudflare Workers: Server-Sent Events

```typescript
// functions/[[route]].ts
app.post('/api/generate-architecture-v2', async (c) => {
  const userInput = await c.req.json();
  const modernOpenAI = new ModernOpenAIService(c.env.OPENAI_API_KEY);
  const result = await modernOpenAI.streamArchitecture(userInput);

  // Stream partial objects as Server-Sent Events
  const stream = new ReadableStream({
    async start(controller) {
      const encoder = new TextEncoder();

      // This is where the magic happens
      for await (const partialObject of result.partialObjectStream) {
        const chunk = `data: ${JSON.stringify(partialObject)}\n\n`;
        controller.enqueue(encoder.encode(chunk));
      }

      controller.enqueue(encoder.encode(`data: [DONE]\n\n`));
      controller.close();
    }
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
      'Access-Control-Allow-Origin': '*',
    },
  });
});
```

## 프런트엔드의 난제: 부분 객체는 지저분하다

여기서부터 재미있어진다. AI는 완성된 객체를 보내지 않는다. 시간이 지나며 조금씩 채워지는 **부분 객체**를 보낸다.

```json

    "nodes": [
      { "id": "workers" }
    ]
  }
}

// Second chunk
{
  "cloudflare": {
    "nodes": [
      {
        "id": "workers",
        "type": "workers",
        "name": "Workers"
      }
    ]
  }
}

// Third chunk
{
  "cloudflare": {
    "nodes": [
      {
        "id": "workers",
        "type": "workers",
        "name": "Workers",
        "subtitle": "Serverless Functions",
        "position": { "x": 100, "y": 200 }
      }
    ]
  }

```

### 4. 자동 레이아웃: 실시간 Dagre 배치

핵심 통찰 하나: **레이아웃을 AI에게 맡기지 말 것**. LLM은 공간 배치에 형편없지만, 논리적 관계를 만들어 내는 데는 강하다. 그래서 우리는 이렇게 했다.

1. `position: { x: 0, y: 0 }`가 붙은 노드는 생성하되 무시하기
2. 스트리밍 업데이트가 올 때마다 Dagre 레이아웃 다시 실행하기
3. 다이어그램이 커질수록 뷰포트를 자동으로 맞추기

```typescript
// src/utils/autoLayout.ts
import dagre from '@dagrejs/dagre';
import type { Node, Edge } from '@xyflow/react';

const nodeWidth = 172;
const nodeHeight = 50;

export const getLayoutedElements = (nodes: Node[], edges: Edge[], direction = 'LR') => {
  if (nodes.length === 0) return { nodes: [], edges };

  // Create fresh graph for each layout (no shared state)
  const dagreGraph = new dagre.graphlib.Graph();
  dagreGraph.setDefaultEdgeLabel(() => ({}));
  dagreGraph.setGraph({
    rankdir: direction,
    nodesep: 150,  // Space between nodes on same rank
    ranksep: 200,  // Space between ranks (layers)
    marginx: 80,   // Graph margin
    marginy: 80
  });

  nodes.forEach((node) => {
    dagreGraph.setNode(node.id, { width: nodeWidth, height: nodeHeight });
  });

  edges.forEach((edge) => {
    dagreGraph.setEdge(edge.source, edge.target);
  });

  dagre.layout(dagreGraph);

  const newNodes = nodes.map((node) => {
    const nodeWithPosition = dagreGraph.node(node.id);
    return {
      ...node,
      position: {
        x: nodeWithPosition.x - nodeWidth / 2,
        y: nodeWithPosition.y - nodeHeight / 2,
      },
    };
  });

  return { nodes: newNodes, edges };
};
```

마법은 스트리밍 컴포넌트 안에서 일어난다. **노드가 하나 추가될 때마다** 레이아웃을 다시 계산한다.

```typescript
// src/components/streaming/StreamingReactFlow.tsx
useEffect(() => {
  if (reactFlowNodes.length > 0) {
    // Re-layout on every streaming update
    const { nodes: layoutedNodesResult, edges: layoutedEdgesResult } = getLayoutedElements(
      reactFlowNodes,
      reactFlowEdges,
      'LR'  // Left-to-right layout
    );

    setLayoutedNodes(layoutedNodesResult);
    setLayoutedEdges(layoutedEdgesResult);

    // Auto-fit viewport to new layout
    setTimeout(() => {
      if (reactFlowInstanceRef.current) {
        reactFlowInstanceRef.current.fitView({ padding: 0.2 });
      }
    }, 50);
  }
}, [reactFlowNodes.length, reactFlowEdges.length]); // Re-run on every count change
```

이 접근법을 쓰면 **반응형 실시간 레이아웃**을 얻는다. 노드가 하나씩 스트리밍될 때마다 Dagre가 전체 레이아웃을 다시 계산하고, 뷰포트는 부드럽게 따라간다. **AI는 논리적 아키텍처를 만들고, Dagre는 시각적 완성도를 맡는다**.

### 5. 프런트엔드: 부분 객체를 우아하게 다루기

```typescript
// src/hooks/useStreamingArchitectureV2.ts
export function useStreamingArchitectureV2() {
  const [object, setObject] = useState<Partial<ArchitectureResponse> | null>(null);

  // Filter out incomplete objects before rendering
  const allCloudflareNodes = object?.cloudflare?.nodes || [];
  const cloudflareNodes = allCloudflareNodes.filter(node => {
    const isComplete = node &&
      typeof node === 'object' &&
      node.id &&
      node.type &&
      node.name &&
      node.position &&
      typeof node.position === 'object' &&
      typeof node.position.x === 'number' &&
      typeof node.position.y === 'number';

    if (!isComplete && node?.id) {
      console.log(`⏳ Incomplete node ${node.id}:`, node);
    }

    return isComplete;
  });

  // Stream processing
  const generateArchitecture = useCallback(async (userInput: UserInput) => {
    const response = await fetch('/api/generate-architecture-v2', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ input: userInput }),
    });

    const reader = response.body?.getReader();
    const decoder = new TextDecoder();
    let buffer = '';

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      buffer += decoder.decode(value, { stream: true });
      const lines = buffer.split('\n');
      buffer = lines.pop() || '';

      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const dataStr = line.slice(6);
          if (dataStr === '[DONE]') break;

          try {
            const partialObject = JSON.parse(dataStr);
            setObject(partialObject); // React re-renders with new data
          } catch (parseError) {
            console.warn('Failed to parse chunk:', dataStr);
          }
        }
      }
    }
  }, []);

  return {
    cloudflareNodes, // Only complete nodes
    // ... other filtered data
    generateArchitecture,
  };
}
```

## 배운 것들: 우리가 발견한 점

### 1. **부분 객체는 조금씩 도착한다**
AI 모델은 노드 하나를 끝낸 뒤 다음 노드를 시작하지 않는다. ID만 있는 Node A를 보내고, 이어서 일부 데이터만 들어 있는 Node B를 보낸 다음, 다시 Node A를 완성할 수 있다. 프런트엔드는 이 흐름을 자연스럽게 받아낼 수 있어야 한다.

### 2. **검증은 필수다**
렌더링하기 전에 부분 객체는 반드시 검증해야 한다. 필수 필드가 빠져 있으면 React Flow가 터진다. UI 전체를 죽이는 것보다 미완성 객체를 건너뛰는 편이 낫다.

### 3. **AI 로직과 시각 레이아웃을 분리하라**
LLM에게 위치 계산을 시키지 말자. 공간 추론을 못한다. AI에게는 논리적 아키텍처를 만들게 하고, 자동 레이아웃은 Dagre.js에 맡기면 된다. 그러면 깔끔하고 간격이 제대로 잡힌 다이어그램이 나온다.

### 4. **Server-Sent Events > WebSockets**
단방향 스트리밍에는 SSE가 WebSockets보다 단순하다. 연결 관리가 필요 없고, 자동 재연결이 되며, 브라우저 지원도 더 낫다.

### 5. **Cloudflare Workers는 스트리밍에 잘 맞는다**
Workers는 놀라울 정도로 스트리밍을 잘 처리한다. `ReadableStream` API는 Vercel AI SDK의 `partialObjectStream`와 완벽하게 맞물린다.

### 6. **점진적 렌더링은 더 나은 UX를 만든다**
사용자는 다이어그램이 실시간으로 쌓여 가는 걸 좋아한다. 전체 시간이 같더라도, 로딩 스피너보다 훨씬 더 인터랙티브하게 느껴진다.

## 결과: 실시간 아키텍처 시각화

우리가 만든 것은 이런 시스템이다.
- 복잡한 구조화 데이터를 실시간으로 스트리밍한다
- 부분 객체를 자연스럽게 처리한다
- 즉각적인 시각 피드백을 제공한다
- Cloudflare의 엣지 네트워크를 통해 전 세계로 확장된다
- 전체 파이프라인에서 타입 안전성을 유지한다

사용자가 "아키텍처 생성"을 누르면, AI가 생각하는 동안 노드와 연결이 곧바로 나타나기 시작한다. 건축가가 실시간으로 청사진을 스케치하는 걸 보는 느낌이다.

## 직접 해보기

핵심 패턴은 단순하다.
1. Vercel AI SDK의 `streamObject()`를 `partialObjectStream`와 함께 사용한다
2. Server-Sent Events로 스트리밍한다
3. 프런트엔드에서 미완성 객체를 걸러 낸다
4. 객체가 완성되는 대로 점진적으로 렌더링한다

이 접근법은 어떤 구조화 데이터에도 통한다. 데이터베이스 스키마, API 응답, 설정 파일, 복잡한 시각화 모두 가능하다.

## 이 패턴이 엣지 기반 초개인화 UI에 주는 의미

이 스트리밍 아키텍처 패턴은 더 큰 가능성을 연다. **실시간으로 적응하는 초개인화 인터페이스**다.

그냥 더 빨리 로드되는 인터페이스가 아니라, 로드되는 동안 사용자 맥락에 맞춰 *진화하는* 인터페이스를 상상해 보자.

- 현재 프로젝트 상태에 따라 나타나는 **대시보드 위젯**
- 사용 패턴에 맞춰 재구성되는 **내비게이션 메뉴**
- 이전 입력에 따라 모습을 드러내는 **폼 필드**
- 탐색하는 동안 계속 갱신되는 **상품 추천**
- 입력하는 동안 제안을 스트리밍하는 **코드 완성**

Cloudflare Workers의 엣지 컴퓨트와 Vercel AI SDK의 구조화 스트리밍을 결합하면 새로운 패러다임이 열린다. **상황에 맞춰 스스로 구성되는 인터페이스**다.

모든 사용자에게 같은 UI를 보내고 클라이언트 측 JavaScript로 개인화하는 대신, 이제 우리는 이렇게 할 수 있다.
1. 엣지에서 **사용자 맥락 분석하기**(위치, 기기, 행동)
2. AI 모델로 **개인화된 UI 구조 생성하기**
3. 생성되는 대로 **인터페이스 컴포넌트 스트리밍하기**
4. 체감 성능을 즉각적으로 만들도록 **점진적으로 렌더링하기**

이 방식은 특히 이런 곳에서 강력하다.
- 사용자 역할마다 스스로 설정되는 **SaaS 대시보드**
- 구매 행동에 맞춰 적응하는 **이커머스 인터페이스**
- 맥락에 맞는 기능을 띄워 주는 **개발자 도구**
- 참여 패턴에 따라 구조를 바꾸는 **콘텐츠 플랫폼**

엣지는 속도를 맡고, AI는 판단력을 보태며, 스트리밍은 그 과정을 끊기지 않게 만든다.

우리는 단지 더 빠른 웹사이트를 만드는 것이 아니다. 사용자마다 고유하게, 생각의 속도에 가깝게, 실시간으로 사고하고 적응하며 모습을 갖춰 가는 인터페이스를 만드는 중이다.

웹 개발의 미래는 코드를 더 빨리 배포하는 데서 끝나지 않는다. 엣지에서 생성하고 스트리밍한 *서로 다른 코드*를 각 사용자에게 보내, 정말로 개인화된 경험을 마법처럼 느껴지게 만드는 일에 가깝다.
