# 제작기: Cloudflare Workers x Vercel AI SDK로 실시간 시스템 아키텍처 스트리밍하기

*AI 모델이 복잡한 구조화 데이터를 생성하는 순간마다, 노드 하나씩, 엣지 하나씩 실시간으로 흘려보내는 아키텍처 다이어그램 생성기 만들기.*

## 문제: 텍스트 스트리밍을 넘어서

대부분의 AI 스트리밍 구현은 텍스트 생성에 집중한다. ChatGPT의 타자기 효과를 떠올리면 된다. 그런데 실시간으로 복잡한 구조화 데이터를 스트리밍해야 한다면? AI 모델이 네트워크 다이어그램을 만들 때, 노드 하나씩, 엣지 하나씩 화면에 그려지는 모습을 보여주고 싶다면?

우리가 **vibetoprod**를 만들며 다룬 문제가 정확히 이것이었다. vibetoprod는 인터랙티브 클라우드 아키텍처 비교를 생성하는 도구다. 완성된 응답을 보기 위해 사용자가 10초 넘게 기다리게 하는 대신, AI가 생각하는 동안 다이어그램이 실시간으로 모습을 갖춰가는 장면을 보여주고 싶었다.

## 우리의 스택: 엣지 우선 스트리밍

우리가 쓴 현대적이고 엣지에 최적화된 스택은 이렇다.

**백엔드:**
- **Cloudflare Workers** - 전 세계 저지연을 위한 엣지 컴퓨팅
- **Hono** - 가벼운 웹 프레임워크(Workers용 Express 같은 것)
- **Vercel AI SDK** - 구조화된 스트리밍의 비밀 소스
- **OpenAI GPT-4** - 우리의 아키텍처 두뇌
- **Zod** - 런타임 스키마 검증

**프런트엔드:**
- **React + TypeScript** - 타입 안전한 UI 컴포넌트
- **React Flow** - 인터랙티브 다이어그램 시각화
- **Server-Sent Events** - 실시간 브라우저 스트리밍

## 마법: `partialObjectStream`

돌파구는 Vercel AI SDK의 `partialObjectStream`에서 나왔다. 대부분의 개발자는 `streamText()`를 알지만, `streamObject()`를 아는 사람은 더 적다. 그리고 그 부분 스트리밍 기능까지 아는 사람은 더더욱 적다.

작동 방식은 이렇다.

### 2. 백엔드: 부분 객체 스트리밍하기

```typescript
// functions/services/modernOpenAIService.ts
import { streamObject } from 'ai';
import { createOpenAI } from '@ai-sdk/openai';

export class ModernOpenAIService {
  private model: any;

  constructor(private apiKey: string) {
    const openai = createOpenAI({
      apiKey: this.apiKey
    });
    this.model = openai('gpt-4o-2024-08-06');
  }

  async streamArchitecture(input: UserInput) {
    const prompt = this.buildPrompt(input);

    return await streamObject({
      model: this.model,
      schema: architectureResponseSchema,
      prompt,
      mode: 'json'
    });
  }
}
```

### 3. Cloudflare Workers: Server-Sent Events

```typescript
// functions/[[route]].ts
app.post('/api/generate-architecture-v2', async (c) => {
  const userInput = await c.req.json();
  const modernOpenAI = new ModernOpenAIService(c.env.OPENAI_API_KEY);
  const result = await modernOpenAI.streamArchitecture(userInput);

  // Stream partial objects as Server-Sent Events
  const stream = new ReadableStream({
    async start(controller) {
      const encoder = new TextEncoder();

      // This is where the magic happens
      for await (const partialObject of result.partialObjectStream) {
        const chunk = `data: ${JSON.stringify(partialObject)}\n\n`;
        controller.enqueue(encoder.encode(chunk));
      }

      controller.enqueue(encoder.encode(`data: [DONE]\n\n`));
      controller.close();
    }
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
      'Access-Control-Allow-Origin': '*',
    },
  });
});
```

## 프런트엔드 과제: 부분 객체는 지저분하다

여기서부터 흥미로워진다. AI는 완성된 객체를 보내지 않는다. 시간이 지나며 조금씩 채워지는 **부분 객체**를 보낸다.

```json
// First chunk
{
  "cloudflare": {
    "nodes": [
      { "id": "workers" }
    ]
  }
}

// Second chunk
{
  "cloudflare": {
    "nodes": [
      {
        "id": "workers",
        "type": "workers",
        "name": "Workers"
      }
    ]
  }
}

// Third chunk
{
  "cloudflare": {
    "nodes": [
      {
        "id": "workers",
        "type": "workers",
        "name": "Workers",
        "subtitle": "Serverless Functions",
        "position": { "x": 100, "y": 200 }
      }
    ]
  }
}
```

### 4. 자동 레이아웃: 실시간 Dagre 배치

핵심 통찰 하나는 이것이다. **AI에게 레이아웃을 맡기지 말 것**. LLMs는 공간 배치에는 약하지만, 논리적 관계를 만들어내는 데는 강하다. 그래서 우리는 이렇게 했다.

1. `position: { x: 0, y: 0 }`을 가진 노드를 생성한다(무시된다)
2. 스트리밍 업데이트가 올 때마다 Dagre 레이아웃을 다시 실행한다
3. 다이어그램이 커질 때마다 뷰포트를 자동으로 맞춘다

```typescript
// src/utils/autoLayout.ts
import dagre from '@dagrejs/dagre';
import type { Node, Edge } from '@xyflow/react';

const nodeWidth = 172;
const nodeHeight = 50;

export const getLayoutedElements = (nodes: Node[], edges: Edge[], direction = 'LR') => {
  if (nodes.length === 0) return { nodes: [], edges };

  // Create fresh graph for each layout (no shared state)
  const dagreGraph = new dagre.graphlib.Graph();
  dagreGraph.setDefaultEdgeLabel(() => ({}));
  dagreGraph.setGraph({
    rankdir: direction,
    nodesep: 150,  // Space between nodes on same rank
    ranksep: 200,  // Space between ranks (layers)
    marginx: 80,   // Graph margin
    marginy: 80
  });

  nodes.forEach((node) => {
    dagreGraph.setNode(node.id, { width: nodeWidth, height: nodeHeight });
  });

  edges.forEach((edge) => {
    dagreGraph.setEdge(edge.source, edge.target);
  });

  dagre.layout(dagreGraph);

  const newNodes = nodes.map((node) => {
    const nodeWithPosition = dagreGraph.node(node.id);
    return {
      ...node,
      position: {
        x: nodeWithPosition.x - nodeWidth / 2,
        y: nodeWithPosition.y - nodeHeight / 2,
      },
    };
  });

  return { nodes: newNodes, edges };
};
```

마법은 스트리밍 컴포넌트에서 일어난다. 레이아웃은 **노드가 추가될 때마다** 다시 계산된다.

```typescript
// src/components/streaming/StreamingReactFlow.tsx
useEffect(() => {
  if (reactFlowNodes.length > 0) {
    // Re-layout on every streaming update
    const { nodes: layoutedNodesResult, edges: layoutedEdgesResult } = getLayoutedElements(
      reactFlowNodes,
      reactFlowEdges,
      'LR'  // Left-to-right layout
    );

    setLayoutedNodes(layoutedNodesResult);
    setLayoutedEdges(layoutedEdgesResult);

    // Auto-fit viewport to new layout
    setTimeout(() => {
      if (reactFlowInstanceRef.current) {
        reactFlowInstanceRef.current.fitView({ padding: 0.2 });
      }
    }, 50);
  }
}, [reactFlowNodes.length, reactFlowEdges.length]); // Re-run on every count change
```

이 접근은 **반응형 실시간 레이아웃**을 제공한다. 노드가 하나씩 들어올 때마다 Dagre가 전체 레이아웃을 다시 계산하고, 뷰포트가 부드럽게 조정된다. **AI는 논리적 아키텍처를 만들고, Dagre는 시각적 완성도를 맡는다**.

### 5. 프런트엔드: 부분 객체를 우아하게 처리하기

```typescript
// src/hooks/useStreamingArchitectureV2.ts
export function useStreamingArchitectureV2() {
  const [object, setObject] = useState<Partial<ArchitectureResponse> | null>(null);

  // Filter out incomplete objects before rendering
  const allCloudflareNodes = object?.cloudflare?.nodes || [];
  const cloudflareNodes = allCloudflareNodes.filter(node => {
    const isComplete = node &&
      typeof node === 'object' &&
      node.id &&
      node.type &&
      node.name &&
      node.position &&
      typeof node.position === 'object' &&
      typeof node.position.x === 'number' &&
      typeof node.position.y === 'number';

    if (!isComplete && node?.id) {
      console.log(`⏳ Incomplete node ${node.id}:`, node);
    }

    return isComplete;
  });

  // Stream processing
  const generateArchitecture = useCallback(async (userInput: UserInput) => {
    const response = await fetch('/api/generate-architecture-v2', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ input: userInput }),
    });

    const reader = response.body?.getReader();
    const decoder = new TextDecoder();
    let buffer = '';

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      buffer += decoder.decode(value, { stream: true });
      const lines = buffer.split('\n');
      buffer = lines.pop() || '';

      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const dataStr = line.slice(6);
          if (dataStr === '[DONE]') break;

          try {
            const partialObject = JSON.parse(dataStr);
            setObject(partialObject); // React re-renders with new data
          } catch (parseError) {
            console.warn('Failed to parse chunk:', dataStr);
          }
        }
      }
    }
  }, []);

  return {
    cloudflareNodes, // Only complete nodes
    // ... other filtered data
    generateArchitecture,
  };
}
```

## 핵심 배움: 우리가 발견한 것

### 1. **부분 객체는 점진적으로 도착한다**
AI 모델은 노드 하나를 완성한 뒤 다음 노드를 시작하지 않는다. ID만 있는 Node A를 보낸 다음, 부분 데이터가 들어간 Node B를 보내고, 그 뒤에 Node A를 완성할 수도 있다. 프런트엔드는 이런 흐름을 자연스럽게 받아낼 수 있어야 한다.

### 2. **검증은 필수다**
렌더링하기 전에 부분 객체를 반드시 검증해야 한다. 필수 필드가 빠지면 React Flow가 크래시된다. UI를 터뜨리는 것보다 불완전한 객체를 건너뛰는 편이 낫다.

### 3. **AI 로직과 시각적 레이아웃을 분리하라**
LLMs에게 위치 계산을 맡기지 말라. 공간 추론은 약하다. AI에게 논리적 아키텍처를 만들게 하고, 자동 레이아웃은 Dagre.js에 맡기면 된다. 그러면 깨끗하고 간격이 잘 잡힌 다이어그램을 얻을 수 있다.

### 4. **Server-Sent Events > WebSockets**
단방향 스트리밍에는 SSE가 WebSockets보다 단순하다. 연결 관리가 필요 없고, 자동 재연결이 있으며, 브라우저 지원도 더 좋다.

### 5. **Cloudflare Workers는 스트리밍에 잘 맞는다**
Workers는 스트리밍을 놀라울 만큼 잘 처리한다. `ReadableStream` API는 Vercel AI SDK의 `partialObjectStream`과 깔끔하게 맞물린다.

### 6. **점진적 렌더링은 더 나은 UX를 만든다**
사용자는 다이어그램이 실시간으로 만들어지는 모습을 좋아한다. 전체 시간이 같더라도 로딩 스피너보다 훨씬 더 인터랙티브하게 느껴진다.

## 결과: 실시간 아키텍처 시각화

우리가 만든 것은 이런 시스템이다.
- 복잡한 구조화 데이터를 실시간으로 스트리밍한다
- 부분 객체를 자연스럽게 처리한다
- 즉각적인 시각 피드백을 제공한다
- Cloudflare의 엣지 네트워크를 통해 전 세계로 확장된다
- 파이프라인 전체에서 타입 안전성을 유지한다

사용자가 "Generate Architecture"를 클릭하면, AI가 생각하는 동안 노드와 연결이 즉시 나타나기 시작한다. 마치 건축가가 실시간으로 청사진을 스케치하는 모습을 보는 것 같다.

## 직접 해보기

핵심 패턴은 단순하다.
1. Vercel AI SDK의 `streamObject()`를 `partialObjectStream`과 함께 쓴다
2. Server-Sent Events로 스트리밍한다
3. 프런트엔드에서 불완전한 객체를 걸러낸다
4. 객체가 완성되는 대로 점진적으로 렌더링한다

이 접근은 데이터베이스 스키마, API 응답, 설정 파일, 복잡한 시각화 등 어떤 구조화 데이터에도 적용할 수 있다.

## 엣지 위의 초개인화 UI에 이것이 의미하는 것

이 스트리밍 아키텍처 패턴은 더 큰 가능성을 연다. **실시간으로 적응하는 초개인화 인터페이스**다.

단지 더 빨리 로드되는 것이 아니라, 로드되는 동안 각 사용자의 맥락에 맞게 *진화하는* 인터페이스를 상상해 보자.

- **대시보드 위젯**이 현재 프로젝트 상태에 따라 나타난다
- **내비게이션 메뉴**가 사용 패턴에 따라 재구성된다
- **폼 필드**가 이전 입력에 따라 모습을 드러낸다
- **상품 추천**이 탐색하는 동안 갱신된다
- **코드 완성**이 입력하는 동안 제안을 스트리밍한다

Cloudflare Workers의 엣지 컴퓨팅과 Vercel AI SDK의 구조화된 스트리밍이 만나면 새로운 패러다임이 생긴다. **스스로 만들어지는 맥락적 인터페이스**다.

모두에게 같은 UI를 보내고 클라이언트 측 JavaScript로 개인화하는 대신, 우리는 이렇게 할 수 있다.
1. 엣지에서 **사용자 맥락 분석**(위치, 기기, 행동)
2. AI 모델로 **개인화된 UI 구조 생성**
3. 만들어지는 즉시 **인터페이스 컴포넌트 스트리밍**
4. 즉각적인 체감 성능을 위해 **점진적으로 렌더링**

이 방식은 특히 다음 영역에서 강력하다.
- **SaaS 대시보드**가 사용자 역할에 맞춰 스스로 구성된다
- **이커머스 인터페이스**가 구매 행동에 맞춰 적응한다
- **개발자 도구**가 맥락에 맞는 기능을 드러낸다
- **콘텐츠 플랫폼**이 참여 패턴에 따라 구조를 바꾼다

엣지는 속도를 준다. AI는 지능을 준다. 스트리밍은 유동성을 준다.

우리는 단지 더 빠른 웹사이트를 만드는 것이 아니다. 각 사용자에게 고유하게, 생각의 속도로, 실시간으로 생각하고 적응하며 모습을 갖추는 인터페이스를 만들고 있다.

웹 개발의 미래는 코드를 더 빨리 내보내는 것만이 아니다. 각 사용자에게 *다른 코드*를 보내는 것이다. 엣지에서 생성되고 스트리밍되어, 정말로 개인화된, 마법처럼 느껴지는 경험을 만드는 것이다.
