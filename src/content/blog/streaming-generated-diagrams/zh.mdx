# 我是怎么做的：用 Cloudflare Workers × Vercel AI SDK 实时流式生成系统架构图

*构建一个实时架构图生成器：AI 模型一边生成复杂的结构化数据，我们一边把它按节点、按边流出来。*

## 问题：不只是把文字流出来

大多数 AI 流式实现都盯着文本生成——想想 ChatGPT 那种打字机效果。但如果你要实时传输的是复杂的结构化数据呢？如果你想在 AI 模型生成网络图的同时，看着它一个节点、一条边地长出来呢？

这正是我们在做 **vibetoprod** 时撞上的问题。它是一个生成交互式云架构对比的工具。我们不想让用户干等十几秒，等一个完整响应啪地掉下来；我们想让他们在 AI 思考的同时，看见图在眼前实时成形。

## 我们的技术栈：边缘优先的流式架构

这是我们这套现代、为边缘端优化的技术栈：

**后端：**
- **Cloudflare Workers** - 用边缘计算换全球低延迟
- **Hono** - 轻量 Web 框架（差不多就是 Workers 版 Express）
- **Vercel AI SDK** - 结构化流式输出真正的杀手锏
- **OpenAI GPT-4** - 我们的架构大脑
- **Zod** - 运行时 schema 校验

**前端：**
- **React + TypeScript** - 类型安全的 UI 组件
- **React Flow** - 交互式图表可视化
- **Server-Sent Events** - 浏览器里的实时流式传输

## 关键魔法：`partialObjectStream`

真正的突破来自 Vercel AI SDK 的 `partialObjectStream`。大多数开发者知道 `streamText()`，但知道 `streamObject()` 的少一些；知道它还能做局部流式输出的，就更少了。

它的工作方式大概是这样：

### 1. 定义 schema

```typescript

const diagramNodeSchema = z.object({
  id: z.string(),

    nodes: z.array(diagramNodeSchema),

    nodes: z.array(diagramNodeSchema),

```

### 2. 后端：流式输出局部对象

```typescript
// functions/services/modernOpenAIService.ts
import { streamObject } from 'ai';
import { createOpenAI } from '@ai-sdk/openai';

export class ModernOpenAIService {
  private model: any;

  constructor(private apiKey: string) {
    const openai = createOpenAI({
      apiKey: this.apiKey
    });
    this.model = openai('gpt-4o-2024-08-06');
  }

  async streamArchitecture(input: UserInput) {
    const prompt = this.buildPrompt(input);

    return await streamObject({
      model: this.model,
      schema: architectureResponseSchema,
      prompt,
      mode: 'json'
    });
  }
}
```

### 3. Cloudflare Workers：Server-Sent Events

```typescript
// functions/[[route]].ts
app.post('/api/generate-architecture-v2', async (c) => {
  const userInput = await c.req.json();
  const modernOpenAI = new ModernOpenAIService(c.env.OPENAI_API_KEY);
  const result = await modernOpenAI.streamArchitecture(userInput);

  // Stream partial objects as Server-Sent Events
  const stream = new ReadableStream({
    async start(controller) {
      const encoder = new TextEncoder();

      // This is where the magic happens
      for await (const partialObject of result.partialObjectStream) {
        const chunk = `data: ${JSON.stringify(partialObject)}\n\n`;
        controller.enqueue(encoder.encode(chunk));
      }

      controller.enqueue(encoder.encode(`data: [DONE]\n\n`));
      controller.close();
    }
  });

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
      'Connection': 'keep-alive',
      'Access-Control-Allow-Origin': '*',
    },
  });
});
```

### 4. 自动布局：Dagre 实时排版

一个关键发现：**不要让 AI 负责布局**。大语言模型很不擅长空间定位，但很会生成逻辑关系。所以我们改成：

1. 生成带有 `position: { x: 0, y: 0 }` 的节点（然后忽略它）
2. 每次收到流式更新，都重新跑一遍 Dagre 布局
3. 随着图变大，自动适配视口

```typescript
// src/utils/autoLayout.ts
import dagre from '@dagrejs/dagre';
import type { Node, Edge } from '@xyflow/react';

const nodeWidth = 172;
const nodeHeight = 50;

export const getLayoutedElements = (nodes: Node[], edges: Edge[], direction = 'LR') => {
  if (nodes.length === 0) return { nodes: [], edges };

  // Create fresh graph for each layout (no shared state)
  const dagreGraph = new dagre.graphlib.Graph();
  dagreGraph.setDefaultEdgeLabel(() => ({}));
  dagreGraph.setGraph({
    rankdir: direction,
    nodesep: 150,  // Space between nodes on same rank
    ranksep: 200,  // Space between ranks (layers)
    marginx: 80,   // Graph margin
    marginy: 80
  });

  nodes.forEach((node) => {
    dagreGraph.setNode(node.id, { width: nodeWidth, height: nodeHeight });
  });

  edges.forEach((edge) => {
    dagreGraph.setEdge(edge.source, edge.target);
  });

  dagre.layout(dagreGraph);

  const newNodes = nodes.map((node) => {
    const nodeWithPosition = dagreGraph.node(node.id);
    return {
      ...node,
      position: {
        x: nodeWithPosition.x - nodeWidth / 2,
        y: nodeWithPosition.y - nodeHeight / 2,
      },
    };
  });

  return { nodes: newNodes, edges };
};
```

真正的魔法发生在流式组件里——**每新增一个节点**，布局就重新计算一次：

```typescript
// src/components/streaming/StreamingReactFlow.tsx
useEffect(() => {
  if (reactFlowNodes.length > 0) {
    // Re-layout on every streaming update
    const { nodes: layoutedNodesResult, edges: layoutedEdgesResult } = getLayoutedElements(
      reactFlowNodes,
      reactFlowEdges,
      'LR'  // Left-to-right layout
    );

    setLayoutedNodes(layoutedNodesResult);
    setLayoutedEdges(layoutedEdgesResult);

    // Auto-fit viewport to new layout
    setTimeout(() => {
      if (reactFlowInstanceRef.current) {
        reactFlowInstanceRef.current.fitView({ padding: 0.2 });
      }
    }, 50);
  }
}, [reactFlowNodes.length, reactFlowEdges.length]); // Re-run on every count change
```

这个做法给了你**响应式的实时布局**：每个节点流进来时，Dagre 都会重算整张图，视口也会顺滑调整。**AI 负责生成架构逻辑，Dagre 负责让画面别长歪**。

### 5. 前端：稳住这些局部对象

```typescript
// src/hooks/useStreamingArchitectureV2.ts
export function useStreamingArchitectureV2() {
  const [object, setObject] = useState<Partial<ArchitectureResponse> | null>(null);

  // Filter out incomplete objects before rendering
  const allCloudflareNodes = object?.cloudflare?.nodes || [];
  const cloudflareNodes = allCloudflareNodes.filter(node => {
    const isComplete = node &&
      typeof node === 'object' &&
      node.id &&
      node.type &&
      node.name &&
      node.position &&
      typeof node.position === 'object' &&
      typeof node.position.x === 'number' &&
      typeof node.position.y === 'number';

    if (!isComplete && node?.id) {
      console.log(`⏳ Incomplete node ${node.id}:`, node);
    }

    return isComplete;
  });

  // Stream processing
  const generateArchitecture = useCallback(async (userInput: UserInput) => {
    const response = await fetch('/api/generate-architecture-v2', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ input: userInput }),
    });

    const reader = response.body?.getReader();
    const decoder = new TextDecoder();
    let buffer = '';

    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      buffer += decoder.decode(value, { stream: true });
      const lines = buffer.split('\n');
      buffer = lines.pop() || '';

      for (const line of lines) {
        if (line.startsWith('data: ')) {
          const dataStr = line.slice(6);
          if (dataStr === '[DONE]') break;

          try {
            const partialObject = JSON.parse(dataStr);
            setObject(partialObject); // React re-renders with new data
          } catch (parseError) {
            console.warn('Failed to parse chunk:', dataStr);
          }
        }
      }
    }
  }, []);

  return {
    cloudflareNodes, // Only complete nodes
    // ... other filtered data
    generateArchitecture,
  };
}
```

## 几个教训：我们实际发现了什么

### 1. **局部对象是分批、逐步到达的**
AI 模型不会先把一个节点写完，再开始下一个。它可能先发来只有 ID 的 Node A，再发来数据还不完整的 Node B，然后才回头补完 Node A。你的前端必须接得住这种混乱。

### 2. **校验非常关键**
渲染前一定要校验这些局部对象。必填字段缺失会直接把 React Flow 弄崩。跳过还没完整的对象，总比把整个 UI 搞挂好。

### 3. **把 AI 逻辑和视觉布局分开**
不要让 LLM 去算坐标——它们的空间推理很差。让 AI 生成逻辑架构，再交给 Dagre.js 做自动布局。这样出来的图才干净，间距也正常。

### 4. **Server-Sent Events > WebSockets**
如果只是单向流式传输，SSE 比 WebSockets 简单。无需连接管理，自动重连，浏览器支持也更好。

### 5. **Cloudflare Workers 很适合做流式传输**
Workers 处理流式传输的表现出奇地好。`ReadableStream` API 和 Vercel AI SDK 的 `partialObjectStream` 配合得很顺。

### 6. **渐进式渲染带来更好的 UX**
用户很喜欢看图实时长出来。哪怕总耗时一样，它也比一个 loading spinner 更有互动感。

## 自己试试看

核心模式很简单：
1. 把 Vercel AI SDK 的 `streamObject()` 和 `partialObjectStream` 搭起来用

3. 在前端过滤局部对象

## 这对边缘端的高度个性化 UI 意味着什么

这种流式架构模式打开的东西更大：**能够实时适应用户的高度个性化界面**。

想象一下，有些界面不只是加载得更快；它们会在加载过程中*演化*，按照每个用户当下的上下文长成不同的样子：

- **仪表盘组件**会根据你当前项目的状态出现
- **导航菜单**会根据你的使用习惯重新组织
- **表单字段**会根据你之前的输入浮现出来
- **产品推荐**会随着你的浏览实时更新
- **代码补全**会在你打字时流式给出建议

Cloudflare Workers 的边缘计算，加上 Vercel AI SDK 的结构化流式传输，合在一起创造了一种新范式：**会自己搭起来的上下文界面**。

也就是说，我们不必把同一套 UI 发给所有人，再靠客户端 JavaScript 做个性化；我们可以：
1. **在边缘端分析用户上下文**（位置、设备、行为）
2. **用 AI 模型生成个性化 UI 结构**
3. **组件一生成，就把它流式传到界面上**
4. **渐进式渲染**，让体感性能几乎即时

这对下面这些场景尤其有用：
- **SaaS 仪表盘**可以按用户角色自我配置
- **电商界面**可以随购买行为调整
- **开发者工具**可以按上下文浮出相关功能
- **内容平台**可以根据互动模式重组内容结构

边缘计算给速度，AI 给判断力，流式传输给顺滑的生成过程。

我们做的不是更快的网站而已；我们在做的是会思考、会适应、会实时成形的界面，而且每个用户看到的都是独一份，速度接近念头冒出来的那一刻。

Web 开发的未来，不只是更快地发布代码。它还会是把*不同的代码*发给不同的用户：在边缘端生成，流式传输，创造出真正个性化、近乎魔法的体验。
